## 2. Цифры с прода

После правок (ПК, 4 worker'а, 7 минут после старта): RSS 1.50 ГБ, куча
главного потока ~50 МБ, event loop p50 20 мс / p99 44 мс / max 64 мс;
worker'ы: Bybit 211 МБ, Binance+Bitget+Gate 140, OKX+KuCoin 116, MEXC+BingX 116.

До правок:

- Процесс: RSS 1.56 ГБ, куча главного потока 57 МБ, event loop p50 20 мс /
  p99 51 мс / max 1.1 с (пики — свёртка SQLite раз в час и retention).
- Запрос к Supabase (пулер `ap-southeast-1`) с ПК: **195 мс**. С VPS в
  Сингапуре будет 2–5 мс — но кеш подписки нужен всё равно: пул на 5
  соединений не выдержал бы 100 клиентов с опросом раз в секунду.
- `history.sqlite`: 1.5 ГБ. Из них `spread_ticks` 320 МБ + индексы 113 МБ
  (мусор), `spread_candles_1h` 356 МБ (3.1 млн часовых свечей, бэкфил на
  полгода), `funding_rates` 180 МБ, `pair_candles_1h` 92 МБ.
- VictoriaMetrics: 161 МБ за 7 дней посекундных точек по ~15 тыс. серий.
- Фронт: `index.js` 753 КБ (237 КБ gzip), source map 2.5 МБ отдавался наружу.
- Стаканы: 124 неглубоких, 11 тыс. запросов/час, средний ответ 380 мс, ошибок 0.

## 3. Что проверили и признали нормальным

- **Авторизация**: initData проверяется HMAC-SHA256 с секретом от токена
  бота, срок 24 ч; `DEV_FAKE_USER=1` при `NODE_ENV=production` роняет старт.
  Админ-маршруты проверяют `isAdmin` по Telegram ID из окружения.
- **SQL**: только параметризованные запросы (`postgres` tagged templates),
  `unsafe` не используется. Ключи бирж шифруются (`KEY_ENCRYPTION_KEY`).
- **Вебхук CryptoBot**: секретный путь + HMAC тела, идемпотентная обработка,
  запасной опрос раз в 3 минуты. Сумма и актив сверяются с заявкой.
- **Оплата**: одна точка выдачи доступа `activate()`; партнёрка и бонусные
  дни там же; ошибка партнёрки не мешает выдать доступ.
- **Движок**: ccxt в worker-потоках, главный поток свободен (p50 20 мс);
  падение потока → биржи переподключаются; `unhandledRejection` логируется,
  а не роняет процесс.
- **Секреты**: `.env`, `.claude/settings.local.json`, `.data`, `.tools` — вне git.

## 4. Находки подробно

### 4.1 Безопасность

- ✅ Лимит запросов (`@fastify/rate-limit`, 600/мин; ключ — Telegram ID из
  заголовка initData, иначе IP; `/api/health` без лимита). Реальный IP —
  через `trustProxy` (Caddy/туннель ставят `X-Forwarded-For`); отключается
  `TRUST_PROXY=0`. Подделка ID лимит обходит, но такие запросы отбивает
  проверка подписи — от DDoS защищает не это, а Caddy/Cloudflare.
- ✅ Заголовки: API — `X-Content-Type-Options: nosniff`, `Cache-Control:
  no-store`; статика через Caddy — `Content-Security-Policy: frame-ancestors`
  с доменами Telegram (Mini App в web.telegram.org живёт в iframe, поэтому
  `X-Frame-Options` ставить нельзя), `Referrer-Policy`, `Permissions-Policy`,
  без заголовка `Server`.
- ✅ Source map фронта больше не публикуется (`VITE_SOURCEMAP=1` для отладки).
- 📝 `/api/health` без авторизации отдаёт память и статистику стаканов —
  не секрет, но при желании можно закрыть за `HEALTH_TOKEN`.
- 📝 Ключи бирж: `KEY_ENCRYPTION_KEY` живёт только в `deploy/.env` —
  бэкап файла обязателен (backup.sh копирует его в `/var/backups/midnex`).

### 4.2 Надёжность

- ✅ Без базы в проде — падение, а не память (см. п. 3 таблицы).
- ✅ SIGTERM/SIGINT → `app.close()`: сборщик дописывает свечи, VictoriaMetrics
  сбрасывает буфер, worker'ы и база закрываются; лимит 10 с.
- ✅ Docker: `restart: unless-stopped`, healthcheck `/api/health` с
  `start-period 60s`, `mem_limit` на контейнер (утечка перезапустит контейнер,
  а не утащит сервер в своп), ротация логов (5 × 20 МБ).
- ⏳ Внешний мониторинг (UptimeRobot/BetterStack на `/api/health`) — включить
  после переезда, оповещение в Telegram.
- 📝 Замёрзшая котировка (биржа держит поток, но не обновляет символ) не
  ловится — только устаревание по `receivedAt`. Детектор «цена не менялась N
  минут при живом потоке» — следующий шаг по качеству данных.
- 📝 SQLite работает синхронно на главном потоке (`node:sqlite`): свёртка
  1m → 5m/1h раз в час и retention раз в сутки дают пики event loop до ~1 с.
  Терпимо; если будет мешать — вынести историю в отдельный worker.

### 4.3 Производительность

- ✅ Подписка в кеше 60 с (`Billing.subscription`), сброс при `activate`,
  `grant`, `revoke`, пробном периоде.
- ✅ Скринер: `screenerBody()` держит JSON и gzip по ключу
  `минСпред|биржи|refreshMs|running` 500 мс (снимок движка и так живёт
  250 мс). Ответ — готовый буфер с `Content-Encoding: gzip`;
  `@fastify/compress` его не трогает. Клиентам без gzip — строка JSON.
  Эффект: стоимость N-го клиента ≈ 0 CPU; раньше — ~5 мс JSON + ~4 мс gzip
  на каждый запрос.
- ✅ Логи запросов выключены в проде; медленные (>2 с) и 5xx — в warn.
- ✅ Статика: предсжатые `.br/.gz` (`apps/web/scripts/precompress.mjs`,
  запускается после `vite build`), `preCompressed` в `@fastify/static`,
  кеш на год для `/assets`.
- ✅ Фронт: `SpreadChart` (lightweight-charts, 186 КБ) и `PairsAdminView`
  грузятся по требованию; `react`/`ui` — отдельные чанки.
- 📝 Полный список строк (900) уходит клиенту каждую секунду ради поиска по
  всем монетам. Следующий шаг при росте — отдавать только проходящие фильтр
  плюс закреплённые, а поиск — отдельным запросом; или WebSocket с дельтами.
  Сейчас это ~9 КБ gzip в секунду на клиента (при ~20 строках выше порога).
- 📝 Кеш снимка в движке — одна запись: коллектор (`minSpread=0`) и клиенты
  (`0.5`) вытесняют друг друга каждые 250 мс. Дёшево, но можно сделать Map.

### 4.4 Данные и диск

- ✅ Сырые тики не пишутся; `retention()` удаляет остаток и делает
  `wal_checkpoint(TRUNCATE)`. Место вернёт `npm run history:vacuum -w @cs/api`
  (при остановленном приложении; на ПК ≈ 1.5 → ~1.1 ГБ).
- ✅ Резервные копии SQLite: `history-maintenance backup` — онлайн-копия
  средствами `node:sqlite`, 7 последних; cron 04:10 через `deploy/backup.sh`,
  последняя копия и `deploy/.env` — в `/var/backups/midnex`.
- 📝 `spread_candles_1h` растёт ~3 МБ/день (без retention, так задумано —
  графики за год). `funding_rates` 180 дней — ок.
- 📝 Supabase: свои бэкапы, в бесплатном плане — 7 дней. Перед запуском
  проверить план/лимиты (пул 6543 в режиме transaction, `max: 5` в коде).

### 4.5 Эксплуатация (VPS)

- ✅ `Dockerfile`: multi-stage, `node:24-alpine`, только прод-зависимости,
  `USER node`, том `/data` (SQLite, кеш тикеров, бэкапы, CPU-профили),
  миграции в образе.
- ✅ `deploy/docker-compose.yml`: `app` + `victoria` (v1.152.0, retention 7d,
  512 МБ) + `caddy` (HTTPS, HTTP/3). Наружу — только 80/443.
- ✅ `deploy/setup.sh`: Ubuntu/Debian, Docker из get.docker.com, своп при
  <5 ГБ, ufw или iptables, `deploy/.env` из `.env.example` с генерацией
  `KEY_ENCRYPTION_KEY` и `CRYPTOPAY_WEBHOOK_SECRET`, миграции, cron-бэкап.
- ✅ `deploy/update.sh`: pull → build → копия SQLite → миграции → `up -d` →
  ожидание health. `deploy/backup.sh`: ежедневно, rclone по желанию.
- ✅ `deploy/README.md`: выбор сервера и региона, проверка доступности
  бирж с сервера, домен и Cloudflare, шаги после запуска (`public_url` в
  Supabase, BotFather, вебхук CryptoBot, мониторинг), команды на каждый
  день, память/потоки, перенос истории с ПК.
- ⏳ Проверить доступность API восьми бирж с IP выбранного VPS **до** оплаты
  сервера на длинный срок (команда в README).

## 5. Ёмкость

Оценка на 4 ГБ / 2 vCPU в Сингапуре:

| Клиентов онлайн | CPU главного потока | Исходящий трафик | Supabase |
| --- | --- | --- | --- |
| 10 | ~25 % (движок + стаканы) | ~0.1 МБ/с | ~1 запрос/с (кеш 60 с) |
| 100 | ~30 % (+2–3 мс на клиента в секунду: HTTP + auth) | ~1 МБ/с | ~2 запроса/с |
| 300 | ~45 % | ~3 МБ/с (≈ 8 ТБ/мес при круглосуточной активности; реально в разы меньше — Mini App опрашивает только пока открыт) | ~5 запросов/с |

Узкое место при росте дальше — не CPU, а трафик полного списка: тогда
включать отдачу только строк выше порога или WebSocket (п. 4.3).

## 6. Чеклист запуска (октябрь)

1. VPS 4 ГБ в Сингапуре/Токио, Ubuntu 24.04; проверка доступности бирж.
2. Домен → A-запись на сервер (Cloudflare — DNS only на время выпуска сертификата).
3. `setup.sh` с `DOMAIN`, токеном бота, `ADMIN_TELEGRAM_ID`, `DATABASE_URL`,
   `CRYPTOPAY_TOKEN`; `STARS_PER_USD` как на ПК.
4. `curl https://<домен>/api/health` — `storage: postgres`, `encryption: true`,
   `workers[*]` живы; в боте `/admin` → «Партнёры».
5. Supabase `app_config.public_url` = `https://<домен>`; CryptoBot webhook →
   новый адрес; BotFather — Main Mini App (для `startapp=`).
6. Перенести `history.sqlite` с ПК (по желанию, README § 7), на ПК — `stop.bat`
   и больше не запускать (два бота с одним токеном → 409).
7. Мониторинг `/api/health` снаружи; сохранить `deploy/.env`.
8. Через сутки: `docker compose ps` (без перезапусков), `/api/health →
   memoryMb`, размер `/var/backups/midnex`.

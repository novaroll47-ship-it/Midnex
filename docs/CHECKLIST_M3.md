# Чек-лист приёмки M3 — хранилище, ключи бирж, сессии

Приложение запущено на ПК, туннель прежний — открывается из бота @midnexbot
кнопкой «Открыть MIDNEX». Бот, туннель и данные бирж после перезапуска на месте.

Отмечай пункты, где что-то не так, — исправлю по списку.

      https://supabase.com/dashboard/project/bilivlcjttmoelqeuwxz/settings/database
      → «Reset database password» → скопируй пароль и впиши в `.env`:
      ```
      DATABASE_URL=postgresql://postgres.bilivlcjttmoelqeuwxz:ПАРОЛЬ@aws-0-ap-southeast-1.pooler.supabase.com:6543/postgres
      ```
      Потом перезапусти: `powershell -ExecutionPolicy Bypass -File deploy\run-local.ps1`.
      Пока `DATABASE_URL` пуст, приложение работает в режиме «память процесса»
      (см. Настройки → О приложении → Хранилище) — всё работает, но данные
      живут до перезапуска.
- [ ] **Токен бота и токен Supabase**, которые ты присылал в чат, стоит
      перевыпустить (BotFather → /revoke; Supabase → Account → Access Tokens).

## 1. Скринер (проверка данных M2, которую ты просил)

- [ ] Открой скринер, выбери 5–10 монет и сравни цены с самими биржами
      (фьючерсы USDT-M). Расхождение в пределах секунды — норма; расхождение
      в разы — пиши, какая монета и какая биржа.
- [ ] Настройки → «Данные бирж»: у всех бирж, кроме Gate, статус live.
      Gate из этой сети недоступна (таймаут), пробует переподключиться раз в
      минуту — это не ошибка кода, на Oracle-сервере должна подняться.
- [ ] Строки с пометкой «подозрительно» (спред >20%) — это коллизии тикеров
      (одна монета под одним именем на разных биржах — разные проекты). Они
      уходят вниз списка и не считаются возможностями. Если видишь такую строку
      у нормальной монеты — скажи какую.

## 2. Вотчлист (закреплённые монеты)

- [ ] Закрепи 2–3 монеты кнопкой-галочкой слева. Они должны уйти наверх списка.
- [ ] Закрой приложение полностью, открой снова — закреплённые на месте
      (хранятся на сервере, а не в телефоне).
- [ ] Открой с другого устройства (ПК/телефон) — тот же список.
- [ ] Настройки → Управление подпиской → выбери тариф Free (лимит 5) —
      шестую монету закрепить нельзя, счётчик «5/5» внизу.

## 3. API-ключи бирж (Настройки → API-ключи)

Нужен ключ хотя бы одной биржи. **Создай тестовый ключ ТОЛЬКО с правами на
фьючерсы, без вывода средств.** Если хочешь проверить защиту — создай второй
ключ с включённым выводом на Binance или Bybit.

- [ ] Список восьми бирж с логотипами, у всех «Не подключено».
- [ ] Нажми на биржу → шторка с полями API key / Secret (+ Passphrase у OKX,
      Bitget, KuCoin) и чек-листом требований.
- [ ] Введи заведомо неверный ключ → «Не удалось: <ответ биржи>», ключ не
      сохраняется, поля остаются для повтора.
- [ ] Введи рабочий ключ без вывода → «Ключ принят · Баланс фьючерсов: N USDT»,
      в списке статус:
      - Binance/Bybit: «Права проверены» (зелёный) — права прочитаны по API;
      - остальные: «Проверка вручную» (жёлтый) — биржа права не отдаёт,
        показан чек-лист.
- [ ] (Если есть) ключ Binance/Bybit **с выводом** → красное предупреждение
      «У ключа есть право на вывод средств. Такой ключ не сохраняется».
- [ ] Нажми на подключённую биржу → видно название и последние 4 символа
      ключа, дата проверки, кнопки «Проверить снова» и «Удалить», строка
      «Ввести другой ключ».
- [ ] «Проверить снова» → статус обновился, дата изменилась.
- [ ] «Удалить» → подтверждение → биржа снова «Не подключено».
- [ ] На главном экране настроек счётчик «Подключено: N» совпадает.
- [ ] Секреты в приложение не возвращаются нигде (только «…1234»).

## 4. Сессии и устройства

- [ ] Настройки → «Сессии и устройства»: текущее устройство с платформой
      (iOS/Android/Telegram Desktop) и версией Telegram.
- [ ] Открой приложение со второго устройства → в списке два устройства.
- [ ] «Завершить другие сессии» → подтверждение → осталось одно. На втором

      устройства забыты, приложение закрывается.

- [ ] Две демонстрационные позиции показываются только в режиме «память

## Что сделано технически (для справки)

- Слой хранения: Postgres (Supabase) или память — переключается наличием
  `DATABASE_URL`; схема `apps/api/migrations/0001_init.sql` уже применена.
- Ключи бирж: AES-256-GCM, ключ шифрования `KEY_ENCRYPTION_KEY` в `.env`
  (сгенерирован; **не терять и не менять** — иначе сохранённые ключи не
  расшифруются). Проверка на бирже запросом баланса; Binance/Bybit — чтение
  прав и отказ при включённом выводе (ТЗ §5.2). Нерабочие ключи не хранятся.
- Вотчлист, сессии, настройки, тариф — на сервере, лимит тарифа проверяет сервер.
- Коммит `470fb70` в ветке main.

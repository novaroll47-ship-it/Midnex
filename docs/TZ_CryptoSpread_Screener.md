# ТЗ: CryptoSpread Screener — Telegram MiniApp для спред-арбитража между биржами

## 1. Общая концепция

Telegram Mini App (WebApp) — автоматизированный терминал для торговли спредами (арбитраж цены одного и того же актива на разных биржах) на перпетуал-фьючерсах. Пользователь подключает свои API-ключи бирж, задаёт параметры риска и торговли, а бот сканирует рынки, находит выгодные спреды и открывает/закрывает парные позиции (лонг на одной бирже, шорт на другой) — вручную с подтверждением, с помощью пользователя (полуавтомат) или полностью самостоятельно (автомат).

Продукт не конкурирует с HFT-ботами за мейджоры (BTC, ETH) специально — в скринер попадают **все монеты без исключения**, совпадающие хотя бы на двух из подключённых бирж, включая монеты с нулевым спредом. Наибольшая ценность — в альткоинах, где спред между биржами может достигать 3–5%.

Монетизация — подписка. Оплата на старте: криптовалюта и Telegram Stars.

---

## 2. Биржи и рынки

- **Только перпетуал-фьючерсы (USDT-margined).** Спот не используется.
- **Полный список бирж (8):** Binance, Bybit, OKX, MEXC, Bitget, BingX, Gate, KuCoin.
- Список монет для сканирования формируется автоматически: пересечение всех торговых пар (тикеров), доступных как перпетуал-фьючерс минимум на 2 из 8 бирж.
- ⚠️ *Проверь и выбери лучше:* тикеры на разных биржах могут называться по-разному для одного актива (например, `1000PEPEUSDT` vs `PEPEUSDT`, разные множители контракта). Нужна таблица нормализации/маппинга тикеров между биржами с учётом contract size, иначе спред посчитается некорректно.

## 3. Экран "Скринер" (главный)

### 3.1 Верхний блок
- Статус бота: Активен/Остановлен (переключатель), текст текущего действия ("Сканирование рынков...")
- Кнопка "Настройки бота" — переход в настройки

### 3.2 Сводные карточки
- Найдено возможностей (кол-во пар со спредом выше порога, заданного пользователем)
- Средний спред (%) по всем найденным
- Частота обновления (например "1 сек")

### 3.3 Фильтры
- Выбор монеты (все / конкретная)
- Выбор биржи (все / конкретная пара бирж)
- Минимальный спред (числовое поле, %)
- Доп. фильтры (иконка настроек): фильтр по фандингу и др. (см. п.7)

### 3.4 Таблица монет
Колонки: Монета (иконка+тикер+название) | Биржа 1 (цена) | Биржа 2 (цена) | Спред ($ и %) | чекбокс выбора | "+" (детали/быстрое действие)

Правила:
- Показываются **все совпадающие монеты**, включая нулевой и отрицательный спред (не только "выгодные") — сортировка по убыванию спреда по умолчанию, с возможностью сортировки по названию/цене.
- Чекбокс — включает монету в список для полу/авто-торговли. Лимит чекбоксов = лимит тарифа (см. п.9): на тарифе 2 нельзя выбрать больше 10 монет для торговли (сам скринер без ограничений).
- Биржа с более выгодной ценой подсвечивается (жёлтым — "откуда покупать/куда продавать" — как в мокапе).
- Автообновление (интервал настраивается в "Основных настройках"), плюс кнопка ручного обновления.

### 3.5 Нижняя навигация
Скринер / Позиции / Настройки

## 4. Экран "Позиции"

### 4.1 Вкладки
Открытые / Закрытые / История

### 4.2 Сводка (для открытых)
Открытых позиций (шт) | Общий PnL | Нереализованный PnL | Капитал в работе (USDT)

### 4.3 Карточка позиции
- Пара: тикер + иконка, обе биржи (Long-биржа / Short-биржа), статус LONG/SHORT
- PnL по паре в USDT и %
- Объём на каждую ногу (в монете и в USDT)
- Средний спред (на момент входа) / Текущий спред (live)
- Плечо
- Время и дата открытия
- Цена открытия по каждой ноге
- Индикатор стратегии, если позиция открыта в фандинг-режиме (бейдж "Фандинг") — задел на будущее (п.7.2)
- Кнопки: Детали / Изменить (доступные параметры закрытия — целевой спред, ручной стоп) / Закрыть позицию (принудительное закрытие обеих ног маркетом)

### 4.4 Автозакрытие
Плашка-напоминание: бот автоматически закрывает позиции при достижении цели или срабатывании риск-условий (см. п.8).

## 6. Логика входа и выхода из позиции

### 6.1 Вход (двухэтапный, минимизация "перекоса ног")
1. Бот определяет, на какой из двух бирж выгоднее/надёжнее выставить лимитный ордер (например, там где книга ордеров глубже или где нужная сторона сделки ближе к текущей рыночной цене).
2. Выставляется **лимитный ордер** на первую ногу.
3. Тайм-аут ожидания исполнения — настраиваемый параметр (рекомендация по умолчанию: 2–5 сек). ⚠️ *Проверь и выбери лучше.*
4. Если лимитка не исполнилась за тайм-аут и условие входа (спред) всё ещё выполняется — **переставляем в маркет**, чтобы не упустить возможность.
5. Вторая нога — **всегда маркет**, с догоном объёма (chase-fill) до тех пор, пока объём второй ноги не сравняется с первой, с ограничением по числу попыток/времени. ⚠️ *Проверь и выбери лучше конкретные числа.*
6. Если после N попыток вторая нога так и не набрала нужный объём — немедленно закрыть то, что открылось на первой ноге, маркетом. Залогировать как "неудачный вход" для статистики и последующей отладки алгоритма.

### 6.2 Выход/закрытие (одноэтапный)
- Закрытие всегда **маркетом на обеих биржах одновременно** — приоритет на гарантированную фиксацию результата, а не на экономию комиссии.
- Триггеры закрытия: достижение целевого спреда (схождение цен), срабатывание риск-лимита (стоп-лосс, тайм-аут удержания), ручное закрытие пользователем.

### 6.3 Полуавтомат vs Автомат
- **Полуавтомат:** при обнаружении подходящей возможности бот показывает пользователю окно подтверждения (детали сделки: монета, биржи, спред, объём, плечо). Если к моменту подтверждения условия изменились (спред упал ниже порога или сделка больше не выгодна) — явное предупреждение в этом же окне, с возможностью отменить. Пользователь подтверждает — бот выполняет вход по логике п.6.1 автоматически.
- **Автомат:** бот выполняет весь цикл (поиск → вход → мониторинг → выход) без подтверждений, в рамках заданных пользователем параметров и риск-лимитов.
- В настройках должна быть галочка/кнопка **"Перейти в автоматический режим"** — переключение из полуавтомата в автомат без пересборки настроек.

## 7. Фандинг (funding rate)

### 7.1 Учёт в расчёте профита
Ожидаемый чистый профит по сделке = спред между биржами **минус комиссии обеих бирж (maker/taker в зависимости от типа ордера) минус/плюс ожидаемый фандинг за время удержания позиции**. Показывать пользователю именно чистую цифру, а не "грязный" спред.

### 7.2 Фандинг как отдельная стратегия (не в первой версии)
Отдельная стратегия — удержание дельта-нейтральной позиции (лонг/шорт) не ради схождения цены, а ради сбора разницы в ставках фандинга между биржами. Логика для будущей реализации (продумать архитектуру сразу, чтобы не переделывать):
- Позиция держится по расписанию выплат фандинга (обычно 3 раза в сутки), а не закрывается по спреду
- Закрытие — когда ставка фандинга перестаёт быть выгодной или разворачивается
- В интерфейсе (тариф/раздел режимов) — присутствует как пункт с пометкой **"Скоро"**, не активна в первой версии, но UI-заготовка нужна сразу.

### 7.3 Фильтр "Только прибыльный фандинг" (в первой версии, для обычного режима)
- Бот **не открывает** позицию по обычной (спред-конвергентной) стратегии, если ожидаемый фандинг за время удержания сделает сделку убыточной.
- Если фандинг съедает **небольшую** часть прибыли (не убыточно, но заметно) — бот **уточняет у пользователя** перед входом (актуально для полуавтомата; в автомате — только если не включена отдельная кнопка "Авто режим", которая снимает необходимость уточнения).

## 8. Риск-менеджмент

Все параметры — настраиваемые пользователем поля в разделе "Риск-менеджмент" настроек, без жёстко зашитых системных значений. Минимальный набор полей:
- Максимальное число одновременно открытых пар-позиций
- Максимальное плечо
- Максимальный объём на одну сделку / максимальная экспозиция на одну монету
- Дневной лимит убытка (авто-стоп бота при достижении)
- Тайм-аут удержания позиции (макс. время, если спред не сходится — принудительное закрытие)
- Лимит попыток догона объёма второй ноги при входе (см. п.6.1)

⚠️ *Проверь и выбери лучше:* разумные значения по умолчанию для новых пользователей (например, макс. 3 одновременные пары, плечо ≤10x), которые предлагаются при первом запуске, но всегда редактируемы.

## 9. Тарифы и подписка

| Тариф | Скринер | Торговля | Ограничение |
|---|---|---|---|
| 1. Скринер | Полный доступ ко всем монетам и биржам | Недоступна | — |
| 2. Ограниченный | Полный доступ | Полу- и автомат доступны | Не более 10 любых монет пользователь может выбрать для торговли (не 10 открытых позиций одновременно, а размер "разрешённого списка") |

- Задел на будущее: другие способы оплаты, фандинг-стратегия как часть/надстройка над тарифом.

## 10. Технические требования

### 10.1 Инфраструктура
- Разработка с нуля.
- Backend-сервер размещать в регионе с минимальным пингом до бирж — рекомендация: **Сингапур** (близко к Bybit, OKX, Bitget, Gate, MEXC, BingX — азиатские биржи) как основной вариант, возможно распределённое размещение (несколько серверов ближе к конкретным биржам) при масштабировании. ⚠️ *Проверь и выбери лучше конкретного облачного провайдера/регион (например AWS ap-southeast-1, GCP asia-southeast1).*

### 10.2 Данные о ценах
- WebSocket-подключения к каждой из 8 бирж для получения цен и стакана в реальном времени по всем совпадающим тикерам.
- Расчётный движок спредов — отдельный сервис, агрегирующий цены и пересчитывающий спреды с частотой не реже, чем заявлено в UI ("Обновление: 1 сек").
- ⚠️ *Проверь и выбери лучше:* считать спред по last price, mid price или с учётом глубины стакана (чтобы избежать проскальзывания при реальном входе) — второе точнее, но сложнее технически.

### 10.3 Исполнение ордеров
- Отдельный торговый модуль (order execution engine), работающий с REST/WebSocket API каждой биржи, реализующий логику п.6.
- Очередь/менеджер задач для параллельного исполнения ног на разных биржах.

### 10.4 Безопасность
- API-ключи пользователей хранятся в зашифрованном виде (например, AES-256, ключ шифрования отдельно от БД).
- Валидация прав ключа при подключении — только фьючерсная торговля, без права вывода (см. п.5.2).
- Telegram-авторизация через стандартный WebApp initData с проверкой подписи.

### 10.5 Архитектура
- Backend: ⚠️ *проверь и выбери лучше стек* (например Node.js/NestJS или Go для высокой производительности сетевого слоя с биржами).
- База данных: пользователи, ключи (зашифрованно), настройки, история позиций/сделок, подписки.
- Frontend: Telegram Mini App (React/Vite рекомендуется для скорости и соответствия дизайну из мокапа), тёмная тема, i18n с первого дня (RU/EN).
- Уведомления: интеграция с Telegram Bot API для отправки сообщений в чат, когда пользователь не в приложении (см. п.11).

### 10.6 Стиль/дизайн
Взять за основу визуал предоставленных мокапов: тёмная тема, зелёный акцент для позитивных значений (прибыль, активный статус), красный — для закрытия/минуса, карточная структура блоков, скруглённые углы, нижняя навигация из 3 вкладок. ⚠️ *Проверь и выбери лучше точную цветовую палитру/отступы по референсным изображениям при вёрстке.*

## 11. Уведомления

- Если пользователь **не находится в MiniApp** — уведомления (найден спред выше порога, открыта/закрыта позиция, сработал риск-лимит, требуется подтверждение в полуавтомате) отправляются **в диалог Telegram-бота**.
- Если пользователь **находится в приложении** — уведомления показываются **только в интерфейсе** (без дублирования в чат бота).
- Настройка порогов и типов уведомлений — в разделе "Уведомления" настроек.

## 12. Порядок разработки и приёмка

- Все блоки функциональности (скринер, позиции, настройки, торговый движок, риск-менеджмент, тарифы) разрабатываются **параллельно**, без строгого деления на MVP-этапы.
- После каждого выполненного пункта — **этап приёмки**: пользователь (заказчик) проверяет результат и при необходимости даёт правки на доработку/переделку конкретного пункта.

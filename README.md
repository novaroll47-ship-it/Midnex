# MIDNEX

> Развёртывание на сервере — [deploy/README.md](deploy/README.md).
> Аудит перед выходом на VPS (сентябрь 2026) — [docs/AUDIT_2026-09.md](docs/AUDIT_2026-09.md).

Telegram Mini App для спред-арбитража на перпетуал-фьючерсах между 8 биржами.
Техзадание — [docs/TZ_CryptoSpread_Screener.md](docs/TZ_CryptoSpread_Screener.md),
утверждённые макеты — `docs/mockup-*.png`.

## Что уже работает (этап M1)

Интерфейс из трёх экранов по макетам. Рыночные данные пока мок — реальные биржи
подключаются на M2. Настройки и позиции уже настоящие: их можно менять, изменения
уходят на сервер и видны во всём приложении.

| Экран     | Состояние                                                                                                        |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| Скринер   | живая таблица со своей прокруткой, фильтры по монете/бирже/мин. спреду, выбор монет чекбоксами                   |
| Позиции   | вкладки Открытые/Закрытые/История, сводка, «Детали» и «Изменить» как отдельные экраны, закрытие с подтверждением |
| Настройки | все разделы из ТЗ §5 открываются и работают: режимы, биржи, уведомления, риск-лимиты, тариф, ключи, язык RU/EN   |

Разделы, которые намеренно не активны, помечены этапом, на котором появятся
(приём API-ключей — M3, testnet и реальные деньги — M5, оплата — M6).

## Требования

- Node.js 20+ (проверено на 24)
- npm 10+

## Быстрый старт

```bash
npm install
```

Скопируй `.env.example` в `.env` — для локального запуска менять ничего не нужно,
`DEV_FAKE_USER=1` уже позволяет открыть приложение в обычном браузере.

```bash
npm run dev
```

Откроется:

- фронтенд — http://localhost:5173
- API — http://localhost:8787 (проверка: `/api/health`)

## Запуск в Telegram

Бот: [@midnexbot](https://t.me/midnexbot). Токен лежит в `.env`
(файл в `.gitignore`, в репозиторий не попадает).

Постоянный адрес приложения даёт сервер — см. [развёртывание](deploy/README.md).
Всё, что ниже, нужно только чтобы показать в Telegram незакоммиченные правки
со своей машины.

Telegram открывает Mini App только по HTTPS-адресу, поэтому локальный сервер
нужно выставить наружу туннелем. Скачай
[cloudflared для Windows](https://github.com/cloudflare/cloudflared/releases/latest)
и запусти:

```bash
cloudflared tunnel --url http://localhost:5173
```

В выводе появится адрес вида `https://<случайно>.trycloudflare.com`. Его нужно
прописать боту как кнопку меню:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setChatMenuButton" -H "Content-Type: application/json" -d "{\"menu_button\":{\"type\":\"web_app\",\"text\":\"MIDNEX\",\"web_app\":{\"url\":\"https://<адрес>.trycloudflare.com\"}}}"
```

После этого в чате с ботом появится кнопка **MIDNEX**, открывающая приложение.

> Адрес быстрого туннеля меняется при каждом перезапуске `cloudflared`, и живёт
> он только пока включён твой ПК. Для постоянной работы — сервер.

> Пока туннель поднят, приложение доступно всем, у кого есть его адрес: при
> `DEV_FAKE_USER=1` авторизация Telegram не проверяется. Для разработки это
> удобно, для боевого стенда — выключай.

> `DEV_FAKE_USER=1` полностью отключает проверку авторизации. Это только для
> локальной разработки: сервер откажется стартовать с этим флагом при
> `NODE_ENV=production`.

## Структура

```
apps/
  web/          React 19 + Vite — интерфейс Mini App
  api/          Fastify — HTTP API, авторизация Telegram, состояние настроек и позиций
packages/
  shared/       типы, справочник бирж, форматирование чисел, значения по умолчанию
docs/           ТЗ, архитектурная записка и утверждённые макеты
```

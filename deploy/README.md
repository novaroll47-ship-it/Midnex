# Развёртывание на Oracle Cloud (Always Free)

Цель — чтобы приложение работало круглосуточно и не зависело от твоего ПК.
После этих шагов у бота будет постоянный HTTPS-адрес, который больше не меняется.

Шаги 1–4 нужно сделать руками в консоли Oracle — доступ к твоему аккаунту есть
только у тебя. Шаг 5 сводится к двум командам.

---

## 1. Аккаунт

Регистрация на [cloud.oracle.com](https://cloud.oracle.com) → Start for free.
Карта нужна только для проверки личности; с ресурсов Always Free списаний нет.

При выборе региона бери **Singapore**, **Tokyo** или **Osaka** — они ближе всего
к серверам бирж, а это понадобится на этапе M5. Регион у бесплатного аккаунта
меняется только пересозданием аккаунта, так что выбирай сразу.

## 2. Сервер

Compute → Instances → **Create instance**.

| Поле  | Значение                                                    |
| ----- | ----------------------------------------------------------- |
| Image | Canonical Ubuntu 24.04                                      |
| Shape | **VM.Standard.A1.Flex**, 2 OCPU / 12 ГБ (входит в Always Free) |
| Сеть  | оставить как есть, **Assign a public IPv4 address** — включено |
| Ключи | Save private key — файл понадобится для входа, второй раз его не скачать |

> Если пишет **Out of host capacity** — это обычная история с бесплатными
> Ampere. Попробуй другой Availability Domain, повтори через несколько часов,
> или возьми shape **VM.Standard.E2.1.Micro** (1 ГБ RAM, тоже Always Free):
> нашему приложению этого хватает, образ собирается и под ARM, и под x86.

Запиши публичный IP инстанса — он дальше везде.

## 3. Открыть порты 80 и 443

Это **два разных** уровня, и нужны оба. Первый — в консоли:

Networking → Virtual Cloud Networks → твой VCN → Security Lists → Default →
**Add Ingress Rules**, добавить два правила:

| Source CIDR | IP Protocol | Destination Port |
| ----------- | ----------- | ---------------- |
| 0.0.0.0/0   | TCP         | 80               |
| 0.0.0.0/0   | TCP         | 443              |

Второй уровень — iptables внутри самой машины — откроет скрипт из шага 5.

## 4. Подключиться

```bash
chmod 400 ~/Downloads/ssh-key.key
ssh -i ~/Downloads/ssh-key.key ubuntu@<IP-сервера>
```

## 5. Развернуть

На сервере:

```bash
sudo apt-get update && sudo apt-get install -y git
git clone <адрес-твоего-репозитория> midnex
cd midnex
sudo TELEGRAM_BOT_TOKEN=<токен от @BotFather> bash deploy/setup.sh
```

Скрипт ставит Docker, открывает порты, выпускает сертификат и запускает
приложение. Занимает 3–5 минут, из них большая часть — сборка образа.

В конце он напечатает адрес вида `https://1-2-3-4.sslip.io` и готовую команду
для привязки кнопки меню к боту. Выполни её — и приложение открывается из чата
с ботом кнопкой **MIDNEX**.

## Дальше

Выкатить новую версию:

```bash
cd ~/midnex && bash deploy/update.sh
```

Посмотреть логи:

```bash
cd ~/midnex/deploy && docker compose logs -f
```

Перезапустить:

```bash
cd ~/midnex/deploy && docker compose restart
```

## Почему адрес такой

`1-2-3-4.sslip.io` — это DNS-сервис, который резолвит имя в записанный в нём же
IP. Он даёт постоянное имя под сертификат Let's Encrypt, не покупая домен.
Адрес меняется, только если сменится IP сервера — а он у инстанса постоянный.

Когда захочешь красивое имя (`app.midnex.io`), достаточно купить домен, направить
его A-записью на тот же IP и поменять `DOMAIN` в `deploy/.env` — Caddy сам
выпустит новый сертификат.

## Что лежит на сервере и не лежит в репозитории

`deploy/.env` создаётся скриптом прямо на сервере и содержит токен бота.
В git он не попадает — это единственное место, где токен хранится в проде.
